# Сбор и исходная таблица

- `__main__.py` собирает исходные данные в `../../data/vulnerabilities.csv`
- `config.py` читает настройки
- `sources.py` получает NVD, OSV, GitHub Advisory, EPSS и CISA KEV
- `sources.py` также получает даты публикации из CVE List
- `bdu.py` добавляет данные БДУ ко всем найденным записям
- `api_client.py` выполняет HTTP-запросы с повторами
- `transform.py` объединяет записи
- `cli.py` сохраняет результат в одну таблицу
- `../../data/raw` - ответы API
- `../../data/vulnerabilities.csv` - итоговая таблица выгрузки

Кандидаты обнаруживаются широким поиском NVD по `PyTorch`/`torch`, а также по пакетам `torch` в OSV и GitHub Advisory. 
Найденные только в OSV или GHSA номера CVE дополнительно проверяются прямым запросом NVD по ID, в том числе для статуса REJECTED.
Записи объединяются по CVE и aliases; поисковое совпадение само по себе не означает, что уязвимость относится к PyTorch. 
В таблицу попадают записи с 2020-01-01 по дату запуска или по дату из `--end`: период проверяется по дате CVE List, а при её отсутствии - по дате NVD, OSV или GHSA.

Сбор запускается командой `uv run python scripts/1_collect_pytorch_vulns`.
`published_cve` - дата CVE List, `published_bdu` - дата БДУ. `in_nvd` показывает наличие записи в NVD; наличие в OSV и GHSA видно по `osv_id` и `ghsa_id`. `cwe_source` хранит пары «CWE - источник»; для NVD отдельно указан автор назначения CWE.
При подсчёте частот учитываются все назначенные CWE, но одна пара CVE/CWE считается один раз. Из CVSS сохраняются только `cvss31_nvd`, `cvss31_cna`, `cvss40`, `cvss_bdu` и `cvss_bdu_version`. `cvss31_cna` содержит только оценку CNA. Единую `cvss40` выбираем по порядку CVE List/CNA → NVD/CNA → NVD/NIST → GHSA → OSV, без выбора максимального балла. Для БДУ выбирается самая новая версия из столбцов выгрузки: 4.0 → 3.1 → 3.0 → 2.0. В текущем файле `bdu_vullist.xlsx` столбец подписан `CVSS 3.0`; такую оценку нельзя переименовывать в 3.1 только по виду вектора.
Поля `affected`, `fixed_version`, `fix_commit`, `fix_date`, `reporter` и `channel` заполняются вручную по первоисточникам из `data/raw` и ссылкам в самих записях.
При генерации скрипт переносит значения ручных полей, `review_status` и `review_notes` по `cve_id` из текущего `../../data/vulnerabilities.csv`; у новых строк они пустые.

После единственного сбора работа ведётся вручную в `vulnerabilities.csv`: проверяются строки с пустым `review_status` по [инструкции](../../data/manual_review.md), заполняются поля и выполняется отбор итоговых колонок. После ручной проверки скрипт повторно не запускается.
