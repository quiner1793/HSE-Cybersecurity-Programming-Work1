# Сбор и исходная таблица

- `__main__.py` собирает исходные данные в `../../data/vulnerabilities.csv`
- `config.py` читает настройки
- `sources.py` получает NVD, OSV, GitHub Advisory, EPSS и CISA KEV
- `bdu.py` добавляет данные БДУ ко всем найденным записям
- `api_client.py` выполняет HTTP-запросы с повторами
- `transform.py` объединяет записи
- `cli.py` восстанавливает вручную заполненные поля и сохраняет результат
- `../../data/raw` - ответы API
- `../../data/vulnerabilities.csv` - итоговая таблица выгрузки

Кандидаты обнаруживаются широким поиском NVD по `PyTorch`/`torch`, а также по пакетам `torch` в OSV и GitHub Advisory. 
Записи объединяются по CVE и aliases; поисковое совпадение само по себе не означает, что уязвимость относится к PyTorch. 
В таблицу попадают записи с 2020-01-01 по дату запуска или по дату из `--end`.

Сбор запускается командой `uv run python scripts/1_collect_pytorch_vulns`.
`source_urls` содержит ссылки для ручной проверки. Поля `fix_commit`, `fix_date`, `reporter` и `channel` сборщик не заполняет автоматически.
До перезаписи таблицы скрипт сохраняет эти четыре поля, а также `review_status` и `review_notes` по `cve_id` из текущего `../../data/vulnerabilities.csv`; у новых строк они пустые.

Вручную проверяются строки с пустым `review_status` по правилам из [инструкции ручной проверки](../../data/manual_review.md). После проверки статус каждой строки должен быть `included` или `excluded`.
